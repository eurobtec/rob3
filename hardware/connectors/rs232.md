By using a CMOS inverter instead of a dedicated MAX232 chip, the designer created a highly cost-effective, passive RS232-to-TTL receiver stage.

## Signal Directions & Operation
- **Top Line (Receive):** The PC sends data out from DB9 Pin 2. It drops across the 10k/100k safety network, enters input Pin 13 of the MM74C04N CMOS inverter, is flipped to safe 5V TTL logic, and leaves Pin 12 to enter the 8031 RXD Pin 10.
- **Bottom Line (Transmit):** The 8031 TXD Pin 11 sends out 0–5V serial data. It passes through a 100k current-limiting resistor into the inverting input Pin 2 of the M34004 Op-Amp. Powered by ±9V, the op-amp boosts and flips this signal out of Pin 1 straight to DB9 Pin 3.

> **Note (DB9 pin 5 is a driven reference, not system GND).** DB9 pin 5 is fed
> by **M34004 pin 14 (OUTPUT 4)** — see `../board/M34004.md`. Channel 4 is an
> inverting ±9 V driver whose input is **8031 P3.5 / T1**. The firmware uses T1
> only as the UART baud generator (**TMOD=0x21**) and **never toggles P3.5**, so
> P3.5 stays static HIGH and OUTPUT 4 holds a **fixed RS-232 level** on pin 5.
> The host sees it as the serial **signal-common / reference** (hence it acts
> like "ground"), but it is a ±9 V op-amp output, **not** a tie to system 0 V.
>
> **Implication for the shorting connector:** `rs232-shorting-connector.md`
> treats pin 5 as a GND strap target (e.g. "short pin 4 → pin 5"). Since pin 5
> is actually a driven op-amp output, that strap would tie a conditioning input
> to a ±9 V reference, **not** to system ground — revisit that analysis before
> building a plug.
